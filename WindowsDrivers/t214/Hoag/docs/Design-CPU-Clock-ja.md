# CPU のクロック切り替え：設計（タスクバー常駐）

作成: 2026-10-25（Claude）

## 目標

- **常駐アプリ:** タスクバーの通知領域に常駐して、CPU のクロックを選べるようにする。L4T（Switchroot の Linux）で、上のバーから電源のモードを選べたのと同じような使い方にする。
  - アイコンを右クリックすると、プロファイルの一覧が出る。
  - アイコンにマウスを乗せると、今のクロック、電圧、SoC の温度が見える。
- **Windows を再起動しなくても、その場で切り替える。**

## 今の状態（事実）

- **起動時:** UEFI R365 以降が、1017.6 MHz・1025 mV にしてから Windows を起動している。
- **クロックの作り方:** PLLX（DFLL は使っていない）。発振器 38.4 MHz を M=2 で割り、N をかけて作るので、19.2 MHz 刻みになる。
- **電圧:** CPU の電源は MAX77621（I2C5 の 0x1B）。6.25 mV 刻み。
- **この個体の電圧表:** speedo ID 3。Linux の `TEGRA210_CPU_CVB_TABLE_ODN` を使う。上限は 1227 mV。
- **R365 で確かめた手順:**
  1. 先に電圧を上げる。
  2. CCLK を CLK_M に退避する。
  3. PLLX を設定し直して、ロックを待つ。
  4. CCLK を PLLX に戻す。
  - PLLP には退避しない。cold boot の後は、PLLP の CPU 向けの出力が止まっているため。
- **温度:** TMP451（I2C1 の 0x4C）で読める。ファンのドライバーも同じ値を使っている。

## プロファイル案

**電圧の決め方:** ODN 表の値（DFLL の閉ループ用）に、40 mV の余裕を足す。PLLX は開ループで電圧の自動調整が無いので、R365 と同じ考え方で余裕を取る。

| 名前 | 実際の周波数 | N | ODN 表 | 設定する電圧 | 扱い |
|---|---|---|---|---|---|
| 省電力 | 614.4 MHz | 32 | 853 mV | 893 mV | 通常 |
| 標準（今と同じ） | 1017.6 MHz | 53 | 985 mV | 1025 mV | 通常（起動時の値） |
| 高め | 1209.6 MHz | 63 | 1051 mV | 1091 mV | 通常 |
| 高性能 | 1420.8 MHz | 74 | 1117 mV | 1157 mV | 通常 |
| 最大寄り | 1574.4 MHz | 82 | 1130 mV | 1170 mV | 通常 |
| 最大 | 1670.4 MHz | 87 | 1168 mV | 1208 mV | 試験的 |
| 定格最大 | 1766.4 MHz | 92 | 1228 mV | 1227 mV（上限） | 試験的。余裕が無い |

- **定格を超えるクロック（1785 MHz 超）について:** 1227 mV を超える電圧が必要になる。最初の版には入れない。L4T のオーバークロックのように、別の段階で、温度と安定性を確かめてから検討する。
- **「試験的」の扱い:** 次のように、ほかのプロファイルと分けて扱う。
  - メニューで警告を出す。
  - ログインしたときに自動では戻さない（不安定なまま起動を繰り返すのを防ぐため）。

## 安全策

1. **電圧の順序:** 上げるときは「電圧 → クロック」、下げるときは「クロック → 電圧」の順にする。
2. **上限の固定:** 周波数と電圧の組み合わせは、ドライバーの中の表だけから選ぶ。アプリからは表の番号しか渡せない。1227 mV は超えない。
3. **ロックの失敗:** PLLX がロックしないときは、元の PLLX と電圧に戻す。
4. **温度の見張り:** ドライバーが1秒ごとに SoC の温度を読む。
   - 80 ℃ 以上になったら、標準（1017.6 MHz）に下げる。
   - 70 ℃ 未満に戻ったら、選んでいたプロファイルに戻す。
   - 温度が3回続けて読めなかったら、標準に下げる。
5. **起動時:** ドライバーは、起動時のクロックを変えない（UEFI の 1017.6 MHz のまま）。前回のプロファイルに戻すのは常駐アプリで、「通常」のプロファイルだけを戻す。
6. **ドライバーが外れるとき:** 標準に戻す。

## 構成

### 1. UEFI R375: DSDT にデバイス CPUC を追加

| 項目 | 内容 |
|---|---|
| `_HID` | `"SWOA0701"` |
| Memory32Fixed | CAR 0x60006000、0x1000（PLLX と CCLK のレジスタ） |
| I2cSerialBusV2 0 | 0x1B（MAX77621、CPU の電源）、`\_SB.I2C5` |
| I2cSerialBusV2 1 | 0x4C（TMP451）、`\_SB.I2C1`、Shared（ファンのドライバーと共用） |

### 2. ドライバー `switchcpu.sys`（KMDF）

- **IOCTL:** デバイスインターフェースを公開して、次の要求を受け付ける。
  - `GET_STATUS`: 今の周波数（PLLX のレジスタから計算）、電圧（MAX77621 から読む）、SoC の温度、選んでいるプロファイル、温度で下げているかどうか
  - `GET_PROFILES`: プロファイルの表
  - `SET_PROFILE`: 表の番号
- **権限:** 管理者のほか、ログインしているユーザー（Interactive）にも読み書きを許す。常駐アプリを、管理者として起動しなくてもよいようにするため。
- **切り替え中の処理:** CAR の操作の間は、IRQL を DISPATCH に上げる。CLK_M に退避している時間は、数百 µs。Windows の時計は CPU のクロックではなく ARM の汎用タイマーを使うので、ずれない。
- **記録:** いつもどおり `Services\switchcpu\Parameters` に書く。

### 3. 常駐アプリ `SwitchClock.exe`

- **作り方:** C# の WinForms（NotifyIcon）。PC の .NET Framework に付いている `csc.exe` でビルドする。Visual Studio は要らない。
  - Win10 ARM64 では x86 のエミュレーションで動く。IOCTL は固定サイズの構造体だけで受け渡すので、問題ない。
- **メニュー:**
  - プロファイルの一覧（今のものにチェック）
  - 「ログイン時に起動」（HKCU の Run）
  - 終了
- **アイコン:** 今のクロックを数字で表示する（例: 「1.4」）。温度で下げているときは色を変える。
- **ツールチップ:** 「1420.8 MHz / 1157 mV / SoC 52 ℃」のように表示する。

## 段階

1. **段階1（R375 + ドライバー + 試験用スクリプト）:** `CpuClock.ps1 -Mode Set -Profile 3` のように、コマンドで切り替えられるところまで作る。
   - 確かめる方法:
     - PLLX の読み戻し
     - ベンチマーク（簡単なループの時間）
     - 温度の見張りの動作
2. **段階2（常駐アプリ）:** タスクバーから選べるようにする。
3. **段階3（あとで検討）:** 定格を超えるオーバークロック。負荷に応じて自動で切り替える機能（Windows の電源プランとの連携）。
