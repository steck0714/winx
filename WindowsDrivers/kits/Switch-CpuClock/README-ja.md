# CPU のクロック切り替え（段階1）：ドライバーと試験用スクリプト

設計は `..\Design-CPU-Clock-ja.md`。段階1では、コマンドでプロファイルを切り替えられるところまでを作った。タスクバーの常駐アプリは段階2で作る。

## 中身

| ファイル | 内容 |
|---|---|
| `switchcpu.sys` | KMDF ドライバー（ARM64、テスト署名）。ソースは `..\SwitchCpuClock\src\` |
| `switchcpu.inf` | `ACPI\SWOA0701`。`\\.\SwitchCpu` を、ログインしているユーザーも読み書きできるようにする |
| `CpuClock.ps1` | Install、Status、Set、Bench、Test、Watch、Remove |

## プロファイル

| 番号 | クロック | 電圧 | 扱い |
|---|---|---|---|
| 0 | 614.4 MHz | 893 mV | 省電力 |
| 1 | 1017.6 MHz | 1025 mV | 標準（UEFI の起動時と同じ） |
| 2 | 1209.6 MHz | 1091 mV | |
| 3 | 1420.8 MHz | 1157 mV | |
| 4 | 1574.4 MHz | 1170 mV | |
| 5 | 1670.4 MHz | 1208 mV | 試験的 |
| 6 | 1766.4 MHz | 1225 mV | 試験的（余裕なし） |

- 電圧は、この Switch（speedo ID 3）の Linux の電圧表に 40 mV を足したもの。1227 mV は超えない。
- 6 は、1227 mV の上限に収まるよう 6.25 mV 刻みで切り下げた結果、1225 mV になっている。

## 安全策

- **温度:** SoC が 80 ℃ 以上になると、ドライバーが標準（1）に下げる。70 ℃ 未満に戻ると、選んでいたプロファイルに戻す。温度が3回続けて読めなかったときも、標準に下げる。
- **PLLX がロックしないとき:** 元のクロックと電圧に戻す。
- **起動時:** ドライバーは起動時のクロックを変えない。再起動すれば、必ず標準に戻る。
- **ドライバーを外すとき:** 標準に戻す。

## 手順

1. **Switch を UEFI R375 で起動する。** ペイロードは `D:\Codex\coreboot-R375.rom`。
2. **このフォルダーを Switch に移す。** 例: `C:\SwitchWOA\CpuClock`。
3. **インストールする。** 結果を写真に撮ってほしい。
   ```bat
   powershell -ExecutionPolicy Bypass -File C:\SwitchWOA\CpuClock\CpuClock.ps1 -Mode Install
   ```
   - `now: 1017.6 MHz, 1025 mV, profile 1` と、プロファイルの一覧が出れば準備は完了。
4. **まず1段だけ上げてみる。**
   ```bat
   powershell -ExecutionPolicy Bypass -File C:\SwitchWOA\CpuClock\CpuClock.ps1 -Mode Set -Profile 2
   ```
   - 固まらずに `now: 1209.6 MHz, 1091 mV` と出れば成功。
5. **自動の試験をする。** 0〜4 を順に試して、それぞれベンチマークを取る。最後は標準に戻す。
   ```bat
   powershell -ExecutionPolicy Bypass -File C:\SwitchWOA\CpuClock\CpuClock.ps1 -Mode Test
   ```
   - `loop/s` がクロックに比例して増えていれば、実際にクロックが変わっている。
   - `loop/s per MHz` の値は、どのプロファイルでもほぼ同じになるはず。
6. **試験的なプロファイル（5、6）は、手で1つずつ試す。** 温度を見ながら試すなら、別のウィンドウで `-Mode Watch` を動かしておく。
7. **結果を共有する。** `-Mode Test` の出力を見せてほしい。

## 結果

- **v1（1.0.0.1）:** Code 10 になった。
  - 原因: TMP451 の接続を開けなかった（`OpenSensorStatus=0x80000011`、DEVICE_BUSY）。ファンのドライバーがすでに使っているため。
  - `PllxBaseAtStart=0x48003502`（M=2、N=53、ロック済み）は、想定どおりだった。
- **v2（1.0.0.2）:** TMP451 を開けないときは、ファンのドライバーの記録（`switchfan\Parameters` の TempSoC。2秒ごとに更新）を温度として使うようにした。
  - `TempSource=2` が、この方法で温度を読んでいるという意味。
  - ファンのドライバーの記録が5秒以上更新されないときは、温度が読めないものとして扱う。

- **v2 の実機結果（2026-10-25）:**
  - `-Profile 2` で 1209.6 MHz・1093 mV になった。固まらなかった。
  - `-Mode Test`: 0〜4 をすべて切り替えられた（エラー 0、SoC 41〜43 ℃）。

    | プロファイル | クロック | loop/s | loop/s per MHz |
    |---|---|---|---|
    | 0 | 614.4 MHz | 111,390,000 | 181,299 |
    | 1 | 1017.6 MHz | 185,470,000 | 182,262 |
    | 2 | 1209.6 MHz | 226,403,333 | 187,172 |
    | 3 | 1420.8 MHz | 264,800,000 | 186,374 |
    | 4 | 1574.4 MHz | 297,193,333 | 188,766 |

  - loop/s がクロックに比例しているので、実際にクロックが変わっている。
  - タスクマネージャーの「速度」は 1.02 GHz のまま変わらない。起動時の値を表示しているだけなので、問題ない。
  - **未確認:** 試験的なプロファイル（5、6）。

## もし固まったら

電源ボタンの長押しで電源を切って、起動し直す。UEFI が標準の 1017.6 MHz に戻すので、元の状態から始まる。固まったプロファイルの番号を教えてほしい。

ドライバーを外すときは `-Mode Remove`。R374 の ROM で起動すれば、CPUC 自体が無くなる。
