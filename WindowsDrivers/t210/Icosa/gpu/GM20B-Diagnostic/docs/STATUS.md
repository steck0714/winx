## 一言

GM20B ドライバは **S0〜S2 まで「理論値」で実装済み**。実機での検証はゼロ。Windows シェル(`gm20b.sys`)は PC 上の検査を全部通っているが、
**Windows 上で一度もロードされていない**。次の実機テスト(土曜)の結果で、S1/S2 の理論値を直す。

## 土曜に分かること

`WINDOWS.md` §3(手順 A〜D)と §4(読み方)。持ち帰る物は `gm20b-logs\<日時>\`(`journal.bin`・`registry.txt`・`journal.txt`・`status.txt`)。
結果から次に決めること:

| 結果 | 次の手 |
|---|---|

## 次にやること(優先順)

1. 土曜の結果で S1 / S2 を直す(最優先。実機の値が理論値に勝つ)。
2. **S3〜S4**: GPCPLL の計算機(単体テスト付き)/ priv ring・タイマ・fuse・floorsweep・LTC・FB フラッシュページ・top テーブル・MC の SMMU 診断(読み取りのみ)。
   `cfg.flags` のビット 20〜23 を予約済み。
3. **S5〜S6**: GMMU・インスタンスブロック・BAR1 / PFIFO・チャネル・セマフォの自己テスト。
4. **S7〜S8**: falcon / ACR / FECS / GPCCS / GR。移植できていない部分は NOT PORTED として正直に列挙する。
5. 電源レールの制御(MAX77621、I2C5)は別ドライバ。必要になる確率が高い(§8 の 1)。作るなら `rail_gpu_set_uv` フックとして、既定では無効のまま。
6. PnP / ACPI のデバイスノード化(現状は固定物理アドレスのレガシー WDM)。

## 守るルール(変えない)

- `bl33.bin` は作らない・弄らない(読み取り専用の参照のみ。sha256 `b28d8c33…94de`)。
- git commit は頼まれたときだけ。鍵・証明書は生成も埋め込みもしない(署名は利用者のテスト証明書)。
- GPL のコードを写さない(レジスタ番地とビット位置の事実のみ)。nvgpu / nouveau の MIT 表示は `NOTICE.md`。
- PMIC・電圧は既定で触らない。MC / SMMU は読み取り専用。CAR は SET/CLR エイリアスだけ書く(ACPI の CPUC と共有)。
- MMIO は HAL 経由の整列 32 ビットのみ。待ちは全て上限付き。危険な操作の前に `STEP` を永続化する。
- サービスはデマンド起動のみ(ブート起動にしない)。
- ガードを足したら、変異(`win/tests/mutate.py`)も足す。

## 再開手順

```

make check              # 全検査(1〜2 分)
make -C win dist        # build/dist/gm20b-win/
```
