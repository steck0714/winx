# Native Vulkan on Switch Lite

## Goal and boundaries

Implement native Windows 11 ARM64 Vulkan acceleration for Switch Lite HDH-001/T214 using Mesa NVK and a Windows GPU kernel backend. The desktop still uses **CPU software rendering**.
Prove GPU execution/readback, then off-screen Vulkan drawing, then stable window presentation. Evaluate DWM's Direct3D-to-Vulkan path separately; a Vulkan triangle is not proof of desktop acceleration.
Do not expand game compatibility. Preserve the working landscape display, Windows installation, other systems, partitions and files.
Use **729.6 MHz** by default; **1228.8 MHz** is optional in the existing `LitePerformanceCheck`. Neither profile has an execution/stability pass.
Publish GPU source only to both repositories' `vulkan-test` branches and pin the firmware's driver submodule to the paired revision. Non-GPU boot/power fixes may be promoted to default only when explicitly requested; leave `sc7-test` paused.
Continue local implementation and necessary validation autonomously. Consolidate corrections before a hardware handoff; do not request a card swap for each small probe change. No reliable completion date is available.
Check current physical disks and mounts immediately before asking for the SD card. If the authorized card is present, identify it and proceed; do not repeat a card-return confirmation based on an earlier snapshot.
Keep this file as the single rolling progress entry, about 100 lines or fewer. History belongs in Git; detailed logs are read only when needed.

## Decisions and evidence

- **Hardware reference.** This unit's Switchroot Ubuntu DT identifies VALI/Switch Lite and enabled GM20B. It exposes GPU apertures at `0x57000000`, `0x58000000`, `0x538f0000`, stall/nonstall SPIs 157/158, reset and IOMMU resources. Windows exposes narrow translated resources while preserving POST display and Hekate carveouts. [DSDT](../../AcpiTables/Dsdt/Dsdt.asl) · [Memory map](../../Include/Device/MemoryMap.h)
- **Physical memory.** Initial buffers are driver-owned, contiguous, uncached and below 4 GiB. Switchroot tags IOMMU addresses with bit 34 and leaves physical addresses untagged. Global GPU/GPUB ASIDs are not rewritten. This is not a Windows IOMMU domain or authorization for arbitrary DMA. [Switchroot addressing](https://github.com/CTCaer/switch-l4t-kernel-nvgpu/blob/1ae0167d360287ca78f5a2572f0de42594140312/drivers/gpu/nvgpu/common/mm/nvgpu_mem.c)
- **SoC aperture policy.** T214 SoC DRAM uses VIDMEM encoding throughout, not only in leaf PTEs. Small PDEs use target 1 plus VOL; other direct targets are zero, with separate bind/volatile flags preserved. Host MMIO checks reject the former selectors, and native WDK tests retain >4 GiB page addresses, paging/queue ordering and failed-retirement ownership. [Resolved aperture helper](https://github.com/CTCaer/switch-l4t-kernel-nvgpu/blob/1ae0167d360287ca78f5a2572f0de42594140312/drivers/gpu/nvgpu/common/mm/nvgpu_mem.c) · [GM20B platform](https://github.com/CTCaer/switch-l4t-kernel-nvgpu/blob/1ae0167d360287ca78f5a2572f0de42594140312/drivers/gpu/nvgpu/os/linux/platform_gk20a_tegra.c)
- **Cold initialization.** The local candidate follows bus/private-ring, FIFO reset/timeouts, LTC count routing, FB setup and BAR1/FB-flush order. Force-run profiles and idle-slowdown suppression remain until a PMU governor exists. Security-fuse policy is only read; failures prevent submission. These close source gaps, not established physical root causes. [Frontend](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/platform/t214_frontend.c)
- **GR access preamble.** Preserve initialized FIFO/memory bits while resetting PGRAPH/BLG/PERFMON. Apply the pinned GM20B GR SLCG/BLCG disable tables, set the two engine gates to RUN/power-AUTO and enable GR FIFO/semaphore access. Reject failed reset/readback or PRI faults before binding a channel; the existing full GPU reset unwinds owned resources. New fields expose the resulting GR state; Stage 307 identifies preamble failure. This does not boot FECS/GPCCS or create a graphics context. [Switchroot GR initialization](https://github.com/CTCaer/switch-l4t-kernel-nvgpu/blob/1ae0167d360287ca78f5a2572f0de42594140312/drivers/gpu/nvgpu/gk20a/gr_gk20a.c)
- **Firmware preparation.** Parse unaligned NETB regions without struct casts; round byte-sized Falcon code to zero-padded words and lay out FECS/GPCCS boot/code/data at 256-byte boundaries. Match the upstream T21x bootstrap-header checksum selectors and 40-bit mapped addresses; these checksums select ABI, not authenticity. Actual NVIDIA 32.7.6 NETB (70,502 bytes, 28 regions) and both boot files pass host parsing/packing/header tests; malformed bounds, wrong boot versions and short output storage fail before writes. The probe reads the three external files from its protected driver directory before power-up and copies the packed bytes into owned GPU memory. No proprietary firmware is embedded or published in Git. Secure ACR and graphics contexts remain open. [Firmware source](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/core/gr_firmware.c)
- **GR bootstrap.** Switchroot non-context initialization, bounded scrub/idle waits, firmware-instance binding and FECS/GPCCS bootstrap precede channel admission. Falcon DMA IDLE must become set; boot starts only after transfer completion. PRIV security selects a stop with explicit status until authenticated ACR exists. GR/FIFO reset precedes MC drain and backing release. Stage 308 and ABI 11 expose the failing step/register; a ready mailbox is not shader execution. [Bootstrap source](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/platform/t214_gr.c)
- **Authenticated image preparation.** `core/acr_firmware.c` parses the official T21x high-security image/bootloader and PMU/FECS descriptors/signatures, then builds the Switchroot WPR headers, LSB records and loader data in owned non-WPR memory. NVIDIA 32.7.6 produces a 76,800-byte WPR image and 97,280-byte staging image. Production/debug selection preserves vendor signature bytes; hardware must still authenticate them. Host format/address tests, ASan/UBSan, actual-file packing and ARM64 kernel-library build pass. The installed probe is unchanged. `platform/t214_acr.c` now implements conservative hardware WPR discovery, PMU reset/scrub, its dedicated instance/aperture binding, top-of-IMEM PIO bootloader upload, and bounded HS HALT/mailbox handling with failure reset. Host models (including stale mailbox, PIO bounds and timeout cleanup), ASan/UBSan and ARM64 compilation pass. Windows backing/loader integration and PMU RTOS command queues remain required; no physical authentication pass is claimed. [Packer](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/core/acr_firmware.c)
- **Memory visibility.** Switchroot explicitly states that FB flush need not reach DRAM. Version 0.1.0.12 adds bounded `0x70010` dirty-L2 writeback followed by `0x70004` clean-line invalidation; physical BAR1/CPU comparisons now pass. A host regression models BAR1-visible data remaining absent from CPU memory until writeback and rejects writeback/invalidation timeouts. CPU MMIO scratch writes are distinct from execution fences. [Switchroot L2 operations](https://github.com/CTCaer/switch-l4t-kernel-nvgpu/blob/1ae0167d360287ca78f5a2572f0de42594140312/drivers/gpu/nvgpu/gk20a/mm_gk20a.c)
- **Diagnostic submission.** The candidate follows the vendor GM20B submission flow: TSG-zero header (one member, timeslice 128 at scale 3), CHID-zero entry, RAMFC address in CCSR, empty initial GP_PUT, and BAR1 notifications after scheduling. Both entries count toward runlist length. WDDM retirement preempts TSG zero, and valid single-channel group status is recognized without accepting idle SRAM. Both GPU fence words remain untouched by CPU MMIO tests. Local fault enables retain bind/scheduler/channel-switch evidence while CPU IRQ outputs stay disabled. Native and host tests separate fault bits from ordinary runlist events. The later hot-channel WDDM path is still unvalidated; its saved-context bootstrap cannot inherit a diagnostic pass. [Switchroot FIFO](https://github.com/CTCaer/switch-l4t-kernel-nvgpu/blob/1ae0167d360287ca78f5a2572f0de42594140312/drivers/gpu/nvgpu/gk20a/fifo_gk20a.c)
- **ENGINE notification.** Switchroot's GM20B fatal/restartable masks exclude PBDMA bit 24. Its ISR acknowledges that lone event and the FIFO summary without requesting channel recovery. The shared probe/channel poll now does the same, then re-reads all sources. Sticky events, accompanying faults and faults arriving during W1C still fail; unknown bits are not ignored. Host regressions prove notification handling cannot manufacture completion. [Fault poll](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/core/fault.c)
- **Allocation lifecycle.** ABI 1 describes byte size and optional CPU visibility, never physical addresses. Real-WDK create/destroy/open/close callbacks select the implicit system-memory segment following the Microsoft GPUVA sample, with only metadata owned by the KMD. Bulk failures roll back new objects without destroying existing resources. Open handles retain Dxgkrnl references until close; local references are released before the OS callback that can synchronously destroy an allocation. Native WinPE tests cover rollback, shared opens, read-only/range checks and immediate destruction. Pages, residency and GPU VA remain VidMm-owned; live adapter/UMD integration is still pending. [Allocation backend](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/windows/allocation.c)
- **VidMm integration.** GM20B tables need 128 KiB backing, so use a dedicated nonzero CPU-visible segment marked `PopulatedFromSystemMemory`; no duplicate suballocator. Validate complete spans and aliases. BuildPagingBuffer snapshots private records; only ordered execution publishes PTEs before TLB MMIO. Partial progress is not completed paging. Residency, actual adapter dispatch and paging fences still need integration. [Paging backend](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/windows/paging_buffer.c) · [WDDM table contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmddi/ns-d3dkmddi-_dxgk_page_table_level_desc)
- **System pages.** The paging builder resolves VidMm PTE segment zero as a resident physical byte address and table-segment entries as offsets. It preserves >4 GiB addresses and rejects bit-34 SMMU tags, malformed spans and the implicit allocation ID used as a PTE segment. It relies on VidMm-held residency; it is not a second page allocator or logical-DMA mapping implementation. [PTE contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dukmdt/ns-d3dukmdt-_dxgk_pte)
- **Internal GPU VA.** CreateProcess reserves one 64 MiB leaf coverage with UMD mapping disabled. A private leaf maps only privileged ring, completion and USERD/fence pages; RAMIN/runlist remain unmapped. Restore reserved PDEs invalidated by VidMm. Emit a USER workload followed by a KERNEL completion packet with WFI enabled. Physical enforcement is unverified. [Internal VA](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/windows/internal_va.c) · [Packet encoder](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/core/submission.c)
- **Context ownership.** Capture retains context/root state independently of activation; admitting later work cannot overwrite the active marker. Activation restores RAMIN and initializes only the complement of the completion value. Failed root changes prevent future stale-root use. No CPU implementation writes a successful GPU completion value. [Contexts](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/windows/context.c)
- **Ordered queue.** Dxgkrnl supplies nonpaged private storage for each DMA submission; admission allocates nothing and accepts no UMD-private payload yet. One worker copies the selected record into driver-owned storage, submits and polls it, then retires the channel before notification. Windows may immediately reuse its original private buffer. Reset failures retain affected references; canceled pending fences never advance completion. [Queue](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/windows/work_queue.c) · [Private-buffer contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmddi/ns-d3dkmddi-_dxgkarg_submitcommandvirtual)
- **Notification and recovery.** Matching the marker is insufficient by itself: disable/preempt, runlist removal, unbind, FB flush and TLB invalidation precede reference release and VidSch notification. Synchronization failure retains an engine-only notice for retry/reset. DMA recovery requires MC drain and clamp/reset readback. No caller-supplied retirement boolean bypasses hardware retirement. [Worker](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/windows/submit_worker.c) · [Channel](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/core/channel.c)
- **Adapter memory queries.** `QUERYSEGMENT4` reports the actual table backing; count-only discovery leaves other fields untouched, and descriptor copies preserve OS extension bytes. GPU-MMU/page-level queries match ordered physical paging and two 128 KiB levels covering 40-bit VA. Physical-adapter queries expose one GPU-MMU execution node. `DRIVERCAPS` and private UMD queries remain unsupported until submission/recovery/UMD integration; no coherent, IOMMU, large-page or display capability is implied. [Query backend](https://github.com/ruje0504-2/Windows-for-Switch-Drivers/blob/vulkan-test/drivers/TegraGpu/windows/query.c)
- **Local tests.** Host checks cover formats, clocks/power, cold initialization and failure paths. Real-WDK ARM64 WinPE tests cover memory-query count/stride/capability contracts, allocation batch rollback/shared lifetime, paging multipass/aliases, distinct context roots, ordered submissions, private-buffer reuse, preempt/reset timeout retention, resume admission and notification cancellation. OS/register operations and simulated GPU writes are explicit substitutes; these tests do not exercise live Dxgkrnl allocation or a physical GPU.
- **Remote diagnostics.** The same `LitePerformanceCheck.exe --gpu-json` queries live status without powering up the GPU. Add `--gpu-729` (or explicitly `--gpu-1228`) for one run by an already elevated caller. It emits all 73 ABI 11 fields to inherited stdout, with no GUI, UAC prompt, retry loop or new log file. Query success exits 0 even if the previous test failed; inspect `fifo_pass`. A run exits 0 only for FIFO readback success, 31 for a test failure, or a Win32 I/O/argument error. The ARM64 executable passes real WinPE no-device/argument checks and device-I/O fixtures for full JSON output including GR state, access modes, denied access, ABI/size mismatch and failed/passing reports. Fixture success is not a physical GPU pass. [Tool source](../../Tools/LitePerformanceCheck/performance-check.c)
- **Scheduler boundary.** The queue is a compiled backend, not an exposed `SubmitCommandVirtual` DDI. Worker statuses cannot be returned directly through that callback. The Microsoft render-only sample leaves virtual submission and TDR callbacks unimplemented; dispatcher, malformed-buffer fence handling, command validation, residency and IRQ/preemption/TDR wiring remain required. [Submission contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmddi/nc-d3dkmddi-dxgkddi_submitcommandvirtual)

## Remaining implementation

1. Connect the queue, paging and ownership modules to a complete render-only WDDM adapter alongside the existing display. Implement real dispatch, residency/command validation, interrupt completion and scheduler preemption/TDR handling.
2. Implement authenticated ACR/WPR bootstrap for the observed T214 PRIV security state, then complete GR initialization and memory/synchronization using nouveau, Switchroot and deko3d. Prove actual GPU execution/readback before claiming shaders work.
3. Port NVK's `nvkmd` discovery, allocation, mapping, submission and wait operations to Windows. Keep NVK's compiler/command generation. Build the ARM64 ICD DLL/JSON and match its device to the WDDM LUID; the Switch backend's Horizon services are not a Windows implementation.
4. Implement `VK_KHR_win32_surface`/swapchain presentation. Mesa's DXGI route requires a D3D12 command queue; its GDI route copies through CPU memory. Demonstrate the chosen GPU-backed route explicitly.
5. Separately evaluate Direct3D-to-Vulkan adaptation that DXGI/DWM can select, including shared surfaces and fence interoperability. Compare compositor frame time, CPU usage and GPU work attributed to `dwm.exe`.
