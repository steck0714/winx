# R365 実機結果（UEFI、2026-10-24）

**[事実]（写真から読んだ値）** **CPU を 1017.6 MHz にできた。**

- **R364 の原因の確認:** `CLK_OUT_ENB_Y=00000340`（bit31 `PLLP_OUT_CPU=0`）。R364 で固まった原因の説明（PLLP から CPU への分岐が無効だった）のとおりだった。`CCLKG_POLICY(0x368)=20008888` で、0x020 と同じ値。
- **電圧:** `step 1: VDD_CPU 950 -> 1025 mV (code C3) ... PASS`
- **クロックの切り替え:** `R365 step 2: CCLK -> CLK_M, PLLX 48001201 -> 40003502 (1017600 kHz) ... PASS (lock after 10 us)`
- **切り替え後:** `CPU after: PLLX_BASE=48003502 (1017600 kHz) CCLK_POLICY=20008888 VOUT=1025 mV`
- **実測:** `loop rate: before=85343/ms after=125925/ms ratio=1.47 (expect 1.47) => about 1019 MHz`
- **その後:** BM92T の処理を続け、受電の判定（`S1=4D80 VSAFE=1 SNK=1 DR=1`）に入っていた。写真はここまで。
- **温度:** 切り替え前で SoC=36℃、ボード=34℃。
- **気になる点:** 切り替え前の BQ が `FAULT=10`（入力の異常）を示していた。BQ の FAULT レジスタは、一度読むまで前の状態を保持する。R363 の状態表示では `FAULT=00` だったので、挿したときの一時的なもの（ラッチ）の可能性が高い。後の状態表示で確認する。
