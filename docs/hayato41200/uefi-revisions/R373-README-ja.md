# R373 — タッチパネルの電源を入れて、DSDT に I2C3 とタッチを追加する（R372 ベース）

## 変更点

### UEFI（`UsbPowerAudit-R373.c`）

ファンを回したあとに、`R373TouchPowerOn()` でタッチパネルを起こす。手順は Hekate の `touch_power_on()` と同じ。

1. リセットピン PJ7 を Low にする（ピン DAP4_SCLK、プルダウン）。
2. MAX77620 の LDO6 を 2.9 V にして、オンにする（I2C5 0x3C、レジスタ 0x2F）。
3. I2C3 のピン（GEN3_I2C）を設定する。CAM_I2C は I2C3 から外す。割り込みピン PX1 は入力、プルアップ。
4. I2C3 のクロックを入れて、リセットを解除する（CLK_M、19.2 MHz）。そのあと `i2c_init(I2C_3)` を呼んで、パケットモードにする。
5. PJ7 を High にして、コントローラーの準備完了イベント（0x10）を待つ。
6. チップ ID を読む。期待値は **3670**（STM FTM4）。
7. システムリセットをかけてから、指の検出をオンにする（0xC3 0x01、0x93、0xA1）。

USB STATUS の表示ごとに、`R373 touch: events=…` と、たまっているイベントを最大3件表示する。

- イベント 3 = 触れた、4 = 離した、5 = 動いた。
- x は 0〜1279、y は 0〜719 くらいになるはず。

### DSDT（`Dsdt-R373.asl`）

| デバイス | 内容 |
|---|---|
| `I2C3` | `SWOA0201`、`_UID` 3、0x7000C500、GSI 124。段階3の I2C ドライバー（v3）がそのまま使える |
| `TCH0` | `SWOA0501`。I2cSerialBusV2 0x49 400 kHz `\_SB.I2C3`、GpioInt Level ActiveLow PullUp 185（PX1） |

`TCH0` のドライバーはまだ無い。デバイスマネージャーでは「不明なデバイス」になるが、それで正常。

## テスト手順

1. **R373 の ROM で起動する。**
2. **起動中の表示を撮る。** 次の行を見たい。
   - `R373 touch: LDO6_CFG … read=ea`（`ea` に近い値なら 2.9 V でオン）
   - `R373 touch: I2C3 clk …`
   - `R373 touch: ready=1 chip=3670 …`
   - `R373 touch: reset=PASS sense-on=PASS`
3. **USB STATUS の表示が出ている間に、画面を指で触る。** 次の STATUS で `R373 touch: ev 03 … x=… y=…` が出れば成功。
4. **Windows まで起動するか確かめる。** デバイスマネージャーで次を見る。
   - I2C コントローラーが3つ（I2C1、I2C3、I2C5）あり、すべて正常か。
   - 不明なデバイス（`ACPI\SWOA0501`）が増えているか。

## 結果（2026-10-25、ユーザー報告）

- **成功した。** USB STATUS に `R373 touch: events=64` が出た。触った場所によって、`ev 05`（動いた）の座標が変わった。例:
  - x=330、y=659
  - x=1203、y=198
- **割り込みについて:** イベントが 64 個たまっていても、`IRQ(PX1)=1`（来ていない）のままだった。FTM4 の割り込みは、初期状態では無効になっている。Windows のドライバーで有効にする。

## もし起動しなくなったら

R372 の ROM で起動すれば、元に戻る。
